# Documentation Structure

This folder organizes all project documentation by purpose and lifecycle stage.

## Folder Organization

### `/guides` ← **Start here for development!**
**Step-by-step guides for getting started and daily development**

- `GETTING_STARTED.md` - **Complete setup walkthrough** (prerequisites, environment, database, dev server)
- `DEVELOPMENT_WORKFLOW.md` - **Daily development patterns** (feature workflow, bug fixes, code standards)
- `DEBUGGING.md` - **Troubleshooting guide** (common errors, debugging techniques, emergency fixes)

**When to read**: 
- New to the project? → Read GETTING_STARTED.md first
- Starting development? → Read DEVELOPMENT_WORKFLOW.md
- Something broken? → Read DEBUGGING.md

### `/requirements`
**Project goals and improvement process**

- `REQUIREMENTS.md` - Complete project goals, functional requirements, success criteria, and constraints
- `SELF_IMPROVE.md` - Self-improvement methodology for Claude Code to enhance the project each session

**When to read**: Start here to understand what the project should accomplish.

### `/tracking`
**Session history and progress tracking**

- `BUILD_STATUS.md` - Current project state verification (build status, test results, performance metrics)
- `IMPROVEMENTS.md` - Log of improvements implemented with Impact/Effort ratings
- `SESSION_SUMMARY.md` - Summary of work completed in the last session
- `COMPLETION_CHECKLIST.md` - Verification that all required steps were completed

**When to read**: Check these to understand what was done previously and what still needs work.

### `/archive`
**Historical plans and verification documents**

- `DELIVERY.md` - Delivery timeline and status
- `openrouter-*.md` - OpenRouter API integration verification documents
- `post-render-*.md` - Old planning and verification documents
- `single-document-*.md` - Document rendering verification documents
- `todo.md` - Historical task list

**When to read**: Reference for context on what was tried or planned previously.

## For Future Sessions

When starting new work:

1. Read `requirements/REQUIREMENTS.md` for project goals
2. Check `tracking/SESSION_SUMMARY.md` to see what was accomplished previously
3. Review `tracking/IMPROVEMENTS.md` for context on what works well
4. Follow `requirements/SELF_IMPROVE.md` before stopping your session

This ensures continuous improvement and keeps the project moving forward productively.
